# 規格書：用地端補未完成片段（v1）

狀態：Approved for implementation
日期：2026-09-04
適用分支：`codex/record-to-text-reliability-v2`
實證基準：群聯上課案（2026-09-04，Vertex AI／gemini-3.8-flash，215.5 分鐘）

---

## 1. 背景與目標

雲端轉錄的未完成段（SAFETY 攔截、失敗）重送雲端不一定會過：SAFETY 判定有隨機性（同一段上次擋、這次過），失敗原因可能重現。目標：允許用本機 Qwen 只轉錄未完成時間區間，拼回雲端稿，新增 API 費用為 $0。

實證（群聯案除錯資訊，工作 `A2365FB8` → 重送工作 `5CAD0DD5`）：

- 215.5 分鐘切 11 段 → 第 10 段兩次 `MAX_TOKENS` 自適應切分 → 共 13 段；第 3 段 `SAFETY` 攔截，其餘完成，耗時 19 分 25 秒，$0.30。
- 重送只打第 3 段（70.7 秒），12 段沿用檢查點（response ID 完全相同），耗時 1 分 14 秒。
- 費用驗算：427,718＋42,445＝470,163（thinking 104,370＋9,811＝114,181），證明重送只收新增段；UI 顯示的是兩次累計（另見 §8 備註）。
- 地端整份稿（`_2.txt`，48,123 字、無時間戳／講者標籤）經模糊錨點定位，可對上缺口 00:39:57–00:59:45，邊界誤差 ±1 句內；但地端同音錯字明顯較多（「答案」→「打嗝」、「常常講」→「廠長」）。

## 2. 範圍

- 補的對象：manifest 中所有**非 completed** 段：`blockedBySafety` ＋ `failed`（含 `MAX_TOKENS` 到頂、網路錯）。`completedWithGaps`（地端才有）不動。
- 不限段數，逐一區間處理；任一區間可獨立成功／失敗。
- LLM 潤飾**不在 v1**（見 §7）。

## 3. 觸發條件與門禁

按鈕「用地端補未完成片段」置於「重送未完成片段」旁（`MainView.swift` 失敗區按鈕列）。啟用條件（全要滿足，否則置灰＋tooltip 說明原因）：

1. 工作是雲端後端，且有 `failure.recoveryDirectory` 含合法 `segment-manifest.json`（沿用 `canResumeCloudJob` 判定，`AppViewModel.swift:1108`）。
2. manifest 至少有 1 個 `blockedBySafety`／`failed` 段。
3. 地端 runtime 可用：Developer Mode 開＋Python／helper／OpenCC 就緒（沿用環境檢查邏輯）。未就緒→置灰並提示缺件清單，不給開工。

## 4. 補段管線

1. 開新工作：snapshot 切 `.localQwen`（語言、詞庫、輸出目錄沿用原工作），另帶雲端檢查點參照＋未完成區間清單（起訖秒）。沿用 `resumeCloudJobFromCheckpoint` 的來源存在性檢查。
2. 每區間：ffmpeg 截取該範圍 → 走現有地端流程（120 秒內切＋helper＋OpenCC，不新增切段邏輯）。
3. 區間天生 ≤20 分鐘（雲端段上限）；若因 manifest 異常超限→整件 fail-closed 並報錯，不硬切。
4. 地端輸出不進時間戳／講者標籤（地端本來就沒產），保留純文字、重排斷句後拼入。
5. 任一區間失敗→該區保留原缺口標記，繼續處理其他區間；全部區間失敗→工作失敗，原雲端稿完全不動。

錨點定位（實作指引）：以雲端缺口前後文為錨點，在地端稿做 exact→fuzzy 兩階段定位；先取多個前錨點由遠到近鏈式收斂，再取後錨點順序驗證；定位失敗→該區間視為失敗（§6），不猜。

## 5. 合併格式

- 雲端已完成段原文一字不動；缺口標記行替換為：頭標記＋地端文字＋尾標記。
- 頭：`【以下約 HH:MM:SS–HH:MM:SS 為本機 Qwen 補稿：無講者標籤與時間戳，品質與他段不同，僅供參考】`
- 尾：`【本機補稿結束，以上約 X 分鐘內容來自地端轉錄；以下回到雲端逐字稿】`
- 合併後全文跑現有輸出契約（UTF-8、非空、無 BOM／NUL、拒 prompt echo）。

## 6. 輸出命名（2026-09-04 修訂：不做原地覆寫）

- 唯一輸出：與原稿**同目錄**、原檔名加 `_補段`，例如 `群聯上課3_逐字稿_補段.txt`。
- 撞名（跑第二次）時沿用現有遞增規則（`_補段_2`…），絕不覆寫前一次成果。
- 原雲端稿、檢查點、地端稿一律不動。不做備份機制（無覆寫即無需備份）。

## 7. LLM：明確不做（v1 範圍外）

不送文本上雲、不改字、不猜講者。理由：

1. 隱私：地端段丟去 Google 即破用地端初衷，須明確同意，不宜順手做。
2. 忠實性：LLM 自動改寫可能修正未錯之處；逐字稿屬證據等級，默改比缺口更危險。
3. 費用歸因：多一次文本來回，須另行標示。

未來 Phase 2 啟動條件（另立規格）：明確 opt-in＋送雲前告知＋diff 預覽＋人工確認寫入。

## 8. UX 與日誌

- 進度：沿用現有 job 進度（補段區間走 helper 進度事件）。
- 日誌關鍵行：「用地端補 N 個未完成區間；已完成雲端段直接沿用，不計 API 費用。」每區間記起訖秒＋字數。
- 完成卡顯示：補上 M／N 段、剩餘缺口（若有）、本次 API 新增費用 $0.00。
- 備註（群聯案發現，順手記，不屬本功能範圍）：重送工作的 token／費用顯示為**兩次累計**而非本次新增；後續可改為「本次新增 X（累計 Y）」。

## 9. Fail-closed 矩陣

| 情況 | 行為 |
|---|---|
| 地端 runtime 缺件 | 不開工，列缺件 |
| 檢查點 manifest 非法／越界 | 拒絕，報原因 |
| 錨點定位失敗 | 該區視為失敗，留缺口標記 |
| 單區間地端失敗 | 該區留缺口標記，其餘繼續 |
| 全部區間失敗 | 工作失敗，雲端稿不動 |
| 合併契約檢查失敗 | 不輸出，留檢查點 |

## 10. 測試計畫

- XCTest：錨點定位（exact／fuzzy／找不到）、多缺口排序合併、空補段拒絕、manifest 越界拒絕、撞名遞增不覆寫。
- Self-test＋`scripts/run-checks.sh` 全綠；完整 XCTest 走 CI gate。
- 實機驗收：以群聯案重放（既有兩份稿只作形狀參考，不進 git）：補段位置誤差 ≤2 句、標記正確、契約全過、API 新增費用 $0。

## 11. 非目標

自動 LLM 潤飾、自動猜講者、雲端↔地端逐句混排、Universal／簽署（打包線事項）。

## 12. 驗收標準

以群聯案缺口版一鍵產出與已驗證 `_3.txt` 等價物：零缺口標記、邊界誤差 ≤2 句、契約全過、API 新增費用 $0。
